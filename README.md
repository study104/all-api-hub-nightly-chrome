# 自助签到中转站 · Chrome 扩展

项目已按功能整理为 **8 个模块**，沿用 JavaScript、React 和 Chrome MV3。
业务源码只维护 `src/`，静态资源维护 `public/`，通过 esbuild 生成
`output/chrome-mv3/`。当前身份核验版本和已有消息、存储格式保持兼容。

## 功能模块

| 模块       | 功能                                                             | 从哪里开始                        |
| ---------- | ---------------------------------------------------------------- | --------------------------------- |
| 账号管理   | 单个/批量添加、CSV 匹配导入、保存编辑、凭据与身份、待恢复账号    | [accounts](src/modules/accounts/) |
| 站点管理   | 站点配置、书签导入、登录与签到方式、本站共用流程                 | [sites](src/modules/sites/)       |
| 学习签到   | 录制手动登录和签到、生成步骤与路线、观察账号身份、结束或取消学习 | [learning](src/modules/learning/) |
| 签到执行   | 单次/批量串行队列、定时、身份核验、回放、取消、后台恢复          | [checkin](src/modules/checkin/)   |
| 滑块验证   | 图片识别、缺口匹配、拖动轨迹、验证码子框架、超时与取消           | [slider](src/modules/slider/)     |
| 代理管理   | 导入、Clash/订阅、真实出口、分配、代理占用与释放                 | [proxies](src/modules/proxies/)   |
| 记录统计   | 执行记录、失败说明、余额、奖励、手动标记与汇总                   | [records](src/modules/records/)   |
| 设置与备份 | 打开方式、版本、口令加密备份、导入预览和迁移                     | [settings](src/modules/settings/) |

模块中的 `service.js` 保存后台业务及公开服务接口；`view.js` 保存功能界面
和客户端规则。学习、签到、滑块的 `content.js` 保存网页中的操作与观察。
滑块没有新增独立管理页面。页面导航和现有交互方式沿用当前版本。

`src/entries/` 负责页面挂载、后台事件、消息路由和跨模块编排。
`src/shared/` 保存平台操作、通信、事务、公共界面及作用域兼容桥接。
`src/vendor/` 保留当前 React、Motion、图标和搜索依赖的发布实现。
两个设计演示页面的源码在 `src/previews/`。

所有站点共用 `src/shared/account-identity.js` 读取、解析和比对当前账号身份。
站点配置只描述接口、资料页和字段位置；每个账号独立保存本站用户 ID 或完整
登录标识。登录、签到、二次登录和学习绑定使用同一套规则，见
[共用账号身份识别说明](docs/account-identity-design.md)。

学习浮窗会自动记录当前用户接口的 JSON 路径和资料字段的位置。也可以点
“选择用户 ID / 选择登录名 / 选择邮箱”，再点页面中自己的身份值；结束学习后，
本站所有账号复用这条读取规则，各自保存自己的身份值。接口与页面规则可以
同时保存，站点编辑里可以查看已学习的字段和标签前缀。

签到流程以 **站点 ID** 为归属：同站点所有账号共用一套流程，任一账号重新学习
会更新本站流程，现有和新增账号后续执行都读取最新版。不同站点分别保存，
即使地址同域名也不借用或同步。账号凭据、用户 ID、代理和签到结果独立保存；
首次执行共享流程的站点账密账号通过自己的登录和稳定身份核验建立绑定，
无需再录制本站流程。模块边界和执行流程见
[站点共用签到流程说明](docs/site-workflow-design.md)。

新增账号首次读取本站登录页并长期保存实际入口；后续使用保存结果，只有手动
更新登录方式时重新读取页面。多个第三方入口按提供方分别选择。
字段随所选入口显示，账号保存自己的具体登录入口，同站点仍共用签到流程。
验证码、扫码和第三方授权在对应页面完成，再核验账号身份。字段、执行及模块衔接见
[按页面选择具体登录入口](docs/login-entry-design.md)。

## 构建与加载

安装 Node.js 后，在项目目录运行：

```sh
npm ci
npm run build
```

在 Chrome 扩展管理页面启用“开发者模式”，选择“加载已解压的扩展程序”，
加载 **`output/chrome-mv3`**。修改 `src/` 或 `public/` 后重新构建，并重新加载扩展。
根目录不再保存第二份可手动修改的扩展发布代码。

运行 `npm run preview:login` 可在 `http://127.0.0.1:4176/` 查看 420px 侧边栏的实际组件。
预览使用本地模拟站点和账号数据，支持检查登录入口、字段切换、添加和编辑；
不会操作扩展中的真实账号或执行网络签到。

如果原来加载的是根目录，Chrome 按解压目录生成的扩展 ID 与新目录不同。
可以先运行 `npm run build:legacy-root` 临时在原目录生成当前版本，继续使用原 ID
读取已有账号并导出加密备份；随后加载 `output/chrome-mv3`、导入备份，
再运行 `npm run clean:legacy-root` 移除临时根目录产物。
这两个命令用于目录迁移，日常开发使用普通 `build`。

构建输出保持多行代码，并生成 source map 和 `build-meta.json`。
后台及内容脚本输出经典 IIFE，管理页、侧边栏与两个预览页输出 ESM。
HTML、manifest、样式、图标和 OpenCV 从 `public/` 复制到产物。
OpenCV 内嵌 WebAssembly，保留当前第三方资源原样。

## 维护与验证

```sh
npm run format
npm run verify
```

`verify` 顺序执行构建、行为测试、模块和资源检查、源码排版检查。
也可以分别运行 `npm test`、`npm run check`、`npm run format:check`。
生成产物和第三方运行库不参与自动排版。

身份测试同时检查模块源码和构建产物，覆盖固定用户 ID、其他账号身份拒绝、
Cookie 残留、学习绑定及稳定身份采样等行为。模块行为测试使用模拟 Chrome
平台调用真实服务，覆盖账号、站点、代理、余额和备份等规则。
静态检查确认 8 个模块都参与构建，并检查页面、Worker、脚本注入和模块引用。
真实站点的登录、签到与验证码仍应按各站点配置进行回归验证。

## 迁移后的代码特点

仓库最初只有压缩发布文件，没有原始 TS/TSX 或 source map。
本次使用 AST 与作用域分析抽取实际业务实现，保留原函数名和模块内 live binding，
以维持初始化、副作用和现有异步行为；已经不是加载旧大包的转发目录。
部分短变量名及兼容绑定仍保留，新的公开 API 和模块职责可以从
[模块维护说明](docs/refactoring-plan.md) 阅读。

`scripts/migration/` 保存一次性抽取工具和归属映射，供迁移审计。
它们需要外部旧版本基线，正常开发、构建和验证不执行这些工具。
