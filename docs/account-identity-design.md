# 共用账号身份识别

所有站点的登录、签到前核验、退出再登录后的核验和学习绑定都调用
`src/shared/account-identity.js`。Chrome 扩展直接运行 JavaScript，身份模块不依赖
Python 或额外的本机服务。

`SiteIdentityResolver` 负责读取当前身份，`parseIdentityResponse` 统一解析接口，
`readVisibleAccountIdentity` 统一读取页面，`compareAccountIdentity` 统一比对，
`identitySampleKey` 和 `stableIdentitySamples` 统一判断连续样本。
页面执行和后台保存账号都复用这些规则。

## 当前身份与目标身份

账号在本站的绑定保存在 `account.identity` 中。站点 ID 决定归属，用户 ID
决定本站的具体用户；不同站点出现相同 ID 不冲突。同站点已有账号的 ID
不能分配给另一个账号。

```js
{
  id: "account-a",
  siteId: "site-a",
  username: "用于登录的账号",
  identity: {
    userId: "299",
    username: "本站实际返回的登录名",
    email: "完整邮箱",
    source: "api"
  }
}
```

有些站点不提供用户 ID。这些站点使用完整用户名或邮箱建立独立绑定，
同站点的其他账号不能占用该登录标识。显示昵称、账号备注和邮箱前缀
不作为唯一身份。

账号编辑页的“本站身份绑定”直接展示已保存的用户 ID、本站登录名、邮箱和身份来源。
尚未保存 ID 时显示“未绑定”；这些字段只读。执行签到时仍重新读取当前会话，
再与此处保存的绑定核对，编辑页中的历史绑定不会单独证明当前已经登录。

目标账号的 ID 和名称是核验条件。当前身份必须从浏览器当前会话下的
接口或明确的个人资料字段读取，不能把目标 ID 填进请求后当成读取结果。
本地用户 JSON 只提供接口需要的当前用户提示，不直接证明登录身份。

## 读取顺序

1. 使用本站配置的当前用户接口；没有配置时探测常见的当前用户接口。
   新增站点和旧站点使用同一个读取器，未知站点也使用这些探测。
2. 普通页面登录先用当前 Cookie 会话读取。接口需要用户提示头时，提示
   来自当前页面存储的用户信息；响应中的用户 ID 才是识别结果。
3. 明确配置的 Token 登录、会话令牌引导和父 / 子域身份接口按本站配置读取。
   明确 Token 认证与浏览器 Cookie 分开，不使用其他账号的令牌。
4. 接口未返回用户 ID 时读取当前页面的可见个人资料字段，包括只读表单、
   定义列表，以及头像、登录名和 ID 徽章组成的当前用户卡片。
5. 当前页信息不足时，进入本站配置的身份资料页，或页面导航中明确的
   “个人资料 / 个人设置”入口。学习工作流仍使用本站已经记录的身份路线。

每次采样都重新读取服务端和页面。只记住成功接口的地址及认证类型，
不缓存身份结果、ID 或凭据。请求禁用缓存，拒绝跳转页和非 JSON 的接口响应。
访问验证页、HTTP 错误、缺少身份字段等原因会分别写入日志。

页面读取排除隐藏节点、登录输入框、用户列表、邀请、公告和排行榜等区域。
简写 `ID:` 只在明确的个人资料字段或当前用户卡片中使用，不扫描整页任意 ID。

## 判断结果

| 情况                                                       | 结果        | 后续处理                                  |
| ---------------------------------------------------------- | ----------- | ----------------------------------------- |
| 已绑定 ID，当前 ID 相同                                    | `confirmed` | 连续样本稳定后继续本站流程                |
| 已绑定 ID，当前 ID 不同                                    | `mismatch`  | 按现有账号切换规则处理，保留原绑定        |
| 已绑定 ID，当前没有 ID                                     | `unknown`   | 继续查资料页；不能用昵称或相同名称覆盖 ID |
| 没有绑定 ID，完整登录名 / 邮箱与目标或已保存的本站名称相同 | `confirmed` | 核验稳定性和首次绑定条件                  |
| 当前身份属于本站其他账号                                   | `mismatch`  | 拒绝绑定和签到                            |
| 同一响应或资料区域出现冲突身份                             | `unknown`   | 停止签到，报告冲突                        |
| 接口和页面均没有可核对字段                                 | `unknown`   | 报告实际读取原因和位置                    |

只有一个账号也不能代替身份证据。“登录成功”和余额不是账号的唯一身份。
退出再登录以后要重新采样；第二次核验通过以后才能保存成功结果及余额差额。

首次账密和 GitHub 绑定要求本轮提交了此账号的凭据，并取得稳定身份；站点自动
生成的用户名不必等于账号备注或第三方用户名，绑定本站实际用户 ID / 登录标识。
首次 Token 绑定
要求使用本账号保存的凭据取得稳定接口身份，后台再次确认凭据归属及其未被更改。
首次手动登录要求
实时接口的完整登录名 / 邮箱精确核对到目标账号。学习绑定要求记录到了本次
登录后的稳定页面身份，核对同一登录阶段的不同页面是否有冲突。
后台保存时再次核对账号归属、凭据提交证明、旧绑定和本站其他账号，拒绝覆盖。

## 站点只配置读取位置

Agent Router 使用：

```js
identitySource: {
  storageKey: "user",
  storageType: "localStorage",
  endpoint: "/api/user/self",
  pagePath: "/console/personal"
}
```

其个人设置卡片中的 `ID: 数字` 由共用页面读取器处理。旧站点配置自动补充
这些默认读取位置，已有自定义配置继续保留。

对于接口字段或页面结构不常见的站点，可以通过站点编辑填写：

```js
identitySource: {
  endpoint: "/whoami",
  pagePath: "/member/preferences",
  responseFields: {
    userId: "result.principal.uid",
    username: "result.principal.screen_name"
  },
  pageFields: {
    userId: "#current-user-id",
    username: "#current-user-name"
  }
}
```

字段映射只描述当前用户数据的位置，不需要另写判断函数。显式字段映射优先于
自动识别，区分用户 ID 与租户 ID 等不同命名空间。
模块不会自动知道任意陌生站点未公开的接口或字段；自动探测和页面读取不足时，
由本站配置或学习流程补充真实读取位置，仍使用同一套身份规则。

## 学习如何取得读取位置

在“学习本站流程”或“学习登录”中，本账号完成登录后，顶层页面同时进行两种采集。

1. 共用页面读取器识别只读资料字段、定义列表或用户卡片时，记录该元素的唯一 CSS
   选择器，以及读取文本、只读值或用户属性的方式。Agent Router 的 `ID: 194516`
   会记录去除 `ID: ` 前缀的规则。
2. 共用接口读取器查看页面已经访问的资源地址，寻找 `/me`、`/self`、`/whoami`、
   `/user/info`、`/account/current` 等当前用户接口，并与常见接口一起进行有界探测。
   它重新发送同源 GET，读取当前登录会话的 JSON；不会把资源地址、本地 JSON
   或已保存的账号 ID 当作登录证明。只有连续两次身份与字段路径一致，才记录
   该接口及 `data.id` 等真实 JSON 路径。

自动识别没有得到资料字段时，浮窗提供“选择用户 ID”“选择登录名”“选择邮箱”：
点击其中一项，再点页面里自己的身份值。点选时会显示元素边框，该次点击不会
交给站点按钮或录入签到动作；按 Esc 可以取消。

例如用户选中 `ID: 194516` 后，站点保存的内容是：

```js
identitySource: {
  pagePath: "/console/personal",
  pageFields: {
    userId: "结构或固定属性生成的唯一 CSS 选择器"
  },
  pageFieldRules: {
    userId: { kind: "text", prefix: "ID: " }
  }
}
```

`194516` 保存到当前账号的 `identity.userId`。选择器不使用身份值作为条件，
不生成 `text=194516` 或 `[data-user-id="194516"]`。下一个账号登录后，
同一选择器会读出它自己的 ID。已有绑定会先核对；如果学习页属于另一个账号，
保存会拒绝覆盖旧绑定。只学登录也会保存身份读取规则，无须先执行一次签到。

浮窗显示当前身份和来源；站点编辑的“身份字段与已学习的读取位置”可以查看
接口路径、JSON 字段、页面选择器和标签前缀。接口和页面来源可以一起保存，
接口遇到访问验证时继续使用本站的个人资料页。

采集逻辑位于 `src/modules/learning/identity-learning.js`，使用共用身份模块，
不为新站点另写比较算法。接口自动探测每个登录阶段、每个页面最多尝试三轮，
成功后不持续轮询，结束学习时再做当前会话核验。只读取已经出现过的当前用户
接口和标准接口；不会遍历账号列表、重放登录 POST、保存响应正文或凭据。

## 共用登录成功识别

`src/shared/login-state.js` 提供 `LoginStateResolver` 和 `classifyLoginState`。
登录前检查、提交后等待、OAuth 返回和退出再登录都复用同一套判断，分别返回
`authenticated`、`pending`、`blocked` 或 `failed`，并附带具体原因。
页面中的统一调用入口是 `readLoginState(site, options)`。任务编排使用返回的状态
对象，不把布尔值 `false` 或一次身份接口空响应解释成“未登录”。

这套入口适用于已有站点和未知新增站点。没有真实登录表单时，即使页面保留登录按钮，
也先读取当前会话；连续两次返回一致的用户身份时进入账号核对。当前用户接口既使用
本站已配置的位置，也发现当前页面实际访问过的 `/me`、`/self` 等接口，并使用共用解析器
识别返回字段。未知站点不依赖特定域名的登录成功判断。

控件扫描按动作含义识别入口。常见问答、帮助、文档和教程中的“第三方”“OAuth”
或“登录”不作为认证动作；普通“登录”链接用于进入登录页，不被归成 OAuth。
实际第三方动作（例如“使用 Contoso 登录”）可以识别为未知提供商，无需先增加提供商名单。
账号菜单内的“退出”可以作为会话证据，编辑器等普通区域内的“退出”不会作为登录证据。

每次签到按以下顺序执行：

1. 等待页面和公告处理，读取当前会话状态。
2. 已确认登录时，直接读取当前用户并核对本账号绑定；不查找 Google 等登录入口。
3. 真实登录表单可直接进入本账号的登录方式。只有入口、没有表单时，先读取当前会话；
   尚未建立会话再进入登录页或展开对应登录方式。准备结束后再次读取会话，
   授权弹窗已完成或页面状态已更新时，转回账号核验。
4. 状态尚未确认时，按本站来源进入资料页继续取证；仍缺少证据就保留当前会话
   并报告读取原因。身份接口请求失败不代表退出成功，也不能触发凭据填写。
5. 账号核验通过后，执行已保存的签到流程并核验本轮结果。

“退出再登录”的第二次登录也使用这个入口。页面仍有可靠登录证据时报告退出
未生效；没有登录或退出证据时报告会话状态待核验；明确显示登录入口后才开始
第二次登录。学习回放的会话恢复同样先读取状态，再决定是否回到登录页。

当前页仍显示登录表单、二次验证码、安全验证或注册 / 绑定步骤时，不能采用
成功标志。页面离开本站时继续等待 OAuth 返回。可见的本站成功标志、真实退出
控件或明确配置的签到控件可以证明登录；没有这些控件时，连续两次读取到一致的
实时接口身份或明确页面身份，也可以确认登录。接口重读失败或身份改变会中断
连续样本，旧样本不能用于补足第二次证据。

OAuth 通过弹窗完成、原标签页地址没有改变时，当前执行继续核验，不等待一个
尚未发生的导航事件。旧学习流程只在已保存的资料页显示身份时，执行器可以先
进入该资料页，再重新核验；页面跳转本身不作为成功证据。登录确认后，仍需
用共用身份模块核对目标账号，错误账号不能签到或覆盖原绑定。

Orevx 的公开前端使用独立 API 域名，默认读取位置由
`src/shared/site-login-recipes.js` 统一提供：

```js
identitySource: {
  storageKey: "auth-user",
  tokenKey: "auth-token",
  tokenHeader: "Authorization",
  tokenPrefix: "Bearer ",
  endpoint: "https://server.orevx.ai/api/user/me",
  pagePath: "/user/profile"
}
```

该配置只匹配 `https://orevx.ai`，已有自定义接口优先。读取器每次使用当前页面
localStorage 或 sessionStorage 中的会话令牌，解析 JSON / CBOR 响应；用户资料
缓存仅作兼容提示。旧站点、新账号及学习采样都会通过共用读取入口得到这个位置。
日志记录接口 HTTP 状态、缺少令牌、HTML 响应或超时，不记录令牌值。

Orevx 的当前用户资料卡片显示 `ID 10496, Registered for 89 days`。
共用页面读取器会识别这个无冒号的 ID 字段。学习保存唯一选择器及
`{ kind: "text", prefix: "ID ", stopAt: "," }`，只读取逗号前的 ID；
注册天数变化或切到其他账号时仍使用同一条规则。ID 及天数不进入站点读取配置。

执行日志使用 `登录状态核验[reason]：具体原因`。缺少登录证据、身份证据冲突、
身份不稳定、等待验证、待完成账号设置及站点明确拒绝登录分别提供对应的失败说明。

## GitHub 参考依据

已阅读 [qixing-jk/all-api-hub](https://github.com/qixing-jk/all-api-hub) 的以下实现：

- [New API 浏览器身份适配器](https://github.com/qixing-jk/all-api-hub/blob/main/src/services/apiAdapters/newApi/account/browserIdentity.ts)：
  从本地用户资料取得兼容请求头的提示，请求 `/api/user/self`，采用服务器
  `success === true` 响应中的 `data.id`。
- [共用浏览器身份核验](https://github.com/qixing-jk/all-api-hub/blob/main/src/services/accountBrowserSession/identityVerification.ts)：
  用当前页面会话发 GET，禁用请求缓存、拒绝跳转，并检查读取期间会话是否改变。
- [已登录会话归属校验](https://github.com/qixing-jk/all-api-hub/blob/main/src/services/apiAdapters/newApi/account/authenticatedSession.ts)：
  将实际用户 ID 与账号保存的 ID 比较，分别报告身份缺失和身份不匹配。

该项目也以共用核验层加站点读取能力来支持不同站点，并没有无须读取来源、
就能保证识别任意网站的算法。本实现沿用“实时当前用户资料 + 固定账号绑定”的
原则，并增加直接点选字段和共用来源学习。

如果站点接口只返回人机验证页面，页面又不显示用户 ID、唯一登录名或完整邮箱，
当前会话就没有可核对的身份。此时返回 `unknown` 并说明尝试过的来源；不能
用余额、昵称、浏览器还留着的用户资料或账号备注推断成功。
